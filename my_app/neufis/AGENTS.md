# 捏欧菲斯项目约束

本文档是本项目后续开发、维护和 AI 协作的约束基线。修改功能前先阅读本文；需求与本文冲突时，以用户最新明确指令为准，并同步更新本文和 README。

## 1. 产品定位

- 产品名称：捏欧菲斯。
- 使用方式：单人使用的私人综合工作台，支持电脑浏览器、vivo 手机浏览器和 PWA 安装模式。
- 产品重点：长期记录、快速录入、模块化管理、历史调取、汇总、编辑、删除、复盘和迁移。
- 输出规范：优先使用清晰的 Markdown 表格，文字简洁，不输出无关说明。
- 当前形态：无构建步骤、无第三方依赖的静态前端应用。
- 当前数据不是云端数据，不具备自动跨设备同步能力。

## 3. 不可破坏的数据约束

- 主存储使用浏览器 `localStorage`，键名为 `neufis-workbench-v1`。
- AI 配置独立使用 `neufis-ai-config-v1`，不得并入主状态或 Excel 备份。
- 当前数据结构版本为 `state.version = 1`。
- 受信任设备状态保存在 `localStorage`，键名为 `neufis-unlocked`；首次验证后跨会话保持登录。
- 任何字段调整都必须兼容已生成记录；需要迁移时采用增量迁移，不得清空旧数据。
- 记录默认长期保留。只有用户明确删除记录或执行「清空本条记录」时才能删除数据。
- 「删除XX模块」只将模块设为停用并从导航隐藏，历史数据仍须保留并能随备份导出。
- 新增模块必须同时创建模块定义和对应数据数组。
- 编辑记录必须保留原记录 `id`；除非有明确迁移方案，不改变现有 ID 语义。
- 所有用户输入在插入 HTML 前必须经过 `escapeHtml` 或等效的安全处理。

## 4. Excel 导入导出约束

- 用户要求可通过 Excel 迁移数据，不得移除「导出 Excel」和「导入备份」。
- 当前导出格式是 Excel 可打开的 HTML `.xls`，并在 `#neufis-backup` 中嵌入完整 JSON 状态。
- 表格页用于人工查看，嵌入 JSON 用于无损恢复；两者必须同时保留。
- 导入本项目导出的 `.xls` 时，必须恢复模块规则、启用状态、设置和全部历史记录。
- 换设备前依赖手动导出、在新设备导入。不得把当前实现描述为实时同步。
- 改动状态结构后，必须验证旧备份仍可导入、新备份可完整回读。

## 5. 模块规则

### 健康管理

- 体重为纯数字并自动绑定日期。
- 排便只记录「是/否」。
- 运动记录「是/否」和运动类型；默认关注羽毛球，但允许扩展其他运动。
- 饮品支持文字和图片备注；当前卡路里为本地估算，不得伪称实时联网结果。
- 周报和月报必须包含体重、运动情况和 BMI；未设置身高时不得伪造 BMI。

### 旅行管理

- 旅行档案包含起止时间、目的地、同行人、住宿、交通和逐日行程。
- 物品清单支持新增、编辑、删除、勾选和取消勾选。
- 单趟旅行支持路线描述、调取、编辑和删除。
- 地图搜索可以提供入口；没有真实地图服务时不得声称已经生成地图。

### 钱包管理

- 每条记录包含日期、收入/支出、金额、消费类别和备注。
- 类别保持细分，并允许后续扩展。
- 月度账单包含总收入、总支出、结余、最高占比支出类目和简短复盘。

### 端端有话说

- 端端是用户的儿子。
- 趣味语录按日期逐条存档，可包含场景。
- 汇总时整理成流畅日记体，不改变语录原意。

### 待办事项

- 固定支持「工作待办」和「生活待办」。
- 每条待办包含事项、截止时间和完成状态。
- 必须支持新增、完成、撤销完成、删除、全部列表和仅未完成列表。

### 股市资讯

- 用于记录股票、指数、资讯来源、摘要和复盘观察。
- 当前没有实时行情接口，不得把手工记录描述为实时市场数据。

### 备用项目管理模块

- 保持可用但规则可为空，等待用户后续定义。
- 用户可以修改规则、停用或删除导航入口，历史记录仍按全局保留规则处理。

## 6. 指令与自动归类

必须保留以下便捷指令：

- `工作台总览`
- `健康周报`
- `健康月报`
- `月度账单`
- `全部待办`
- `仅未完成事项`
- `清空本条记录`
- `导出全部记录`
- `新增XX模块`
- `删除XX模块`
- `修改XX模块规则：新的规则内容`

自动归类可以扩展关键词，但必须遵守：

- 纯数字默认作为体重记录。
- 能确定归属时记录到对应模块，并更新 `lastEntry`。
- 无法可靠判断归属时只做简短询问，不擅自保存。
- 动态模块规则必须进入 `state.modules`，不能只改界面文案。
- 新增指令时不能改变现有指令的含义。

## 7. 登录与隐私边界

- 动态验证码规则为：`20230306 + 当天日期（YYYYMMDD）`。
- 日期以设备当前本地日期为准，格式固定为八位数字。
- 登录页不得显示规则、拼接格式、固定前缀、当日答案或可推导答案的示例。
- 验证失败只显示通用错误信息。
- README 和本文可记录规则，应用可见页面不得记录。
- 同一浏览器首次验证成功后写入受信任设备状态；后续启动直接进入工作台。
- 用户主动点击锁定时必须删除受信任设备状态，使下一次启动重新验证。
- 当前验证码在静态前端执行，只是轻量访问锁，不得描述为服务端认证或强安全方案。
- 不在日志、报表、导出文件或错误提示中写入用户输入的验证码。

### AI 隐私边界

- 支持 DeepSeek、Kimi、通义千问和自定义 OpenAI 兼容文本接口。
- 每家厂商单独保存 API Key；只有连接测试成功并记录 `verifiedAt` 后才能调用。
- 已保存 API Key 不得回填到输入框或插入 DOM，只能显示末四位掩码。
- API Key 不得进入 `state`、Excel、Markdown 导出、控制台日志、提示词、错误文案或 Service Worker 缓存。
- 首次调用前必须提示相关文本或图片会直接发送给当前厂商，并取得一次本地确认。
- AI 识别候选在用户确认前不得修改 `state`；取消预览不得产生记录。
- AI 输出必须按模块允许字段过滤并校验日期、数字和枚举；非法响应不得写入。
- 所有 AI 输出使用 `textContent`、DOM 属性或转义后的 HTML 展示，不得执行返回的 HTML。
- 图片最长边缩放到 1600px，转 JPEG 0.82，限制 15 MB，只在请求期间保留，不写入本地存储。
- DeepSeek 和自定义接口首版不得接收图片；图片任务应提示切换至 Kimi 或通义千问。
- AI 请求超时 45 秒且不自动重试；重新识别必须由用户手动触发。
- 不接入实时搜索。热量必须标记为估算，股市只能整理用户提供的材料。

## 8. 视觉与响应式约束

- 主色调保持克制的灰蓝色，同时保留小猪图标的粉色识别点。
- 桌面端大于 900px 时使用左侧约 280px 模块导航、右侧内容区。
- 900px 及以下改为单列，模块导航在顶部横向滑动。
- 640px 及以下表单改为单列，按钮触控高度不低于 44px，输入字号不低于 16px。
- 640px 及以下将工作台总览、Excel 导入/导出和安装入口收进设置图标菜单。
- 在 360px 和 393px 宽度下，`body.scrollWidth` 不得大于视口宽度。
- iOS Safari 的原生日期控件必须保持 `min-inline-size: 0` 和 `max-inline-size: 100%`，不得撑出字段容器。
- 宽表格必须在 `.table-wrap` 内横向滑动，不能撑宽整个页面。
- 导航、快捷指令可以局部横向滑动，但不得遮挡后续内容。
- 文本不得溢出按钮或与相邻控件重叠。
- 页面区块保持紧凑工作台风格，不改成营销落地页。

## 9. PWA 约束

- 项目、部署和交付描述一律以 `neufis/` 为根目录，不得添加额外的上级目录。
- PWA 资源一律使用相对路径，确保从 `neufis/` 根目录直接部署。
- 安装和 Service Worker 离线能力要求 HTTPS；局域网 HTTP 地址只用于测试。
- 修改 `index.html`、`styles.css`、`app.js`、清单或图标后，必须更新 `service-worker.js` 的 `CACHE_NAME`。
- 新增离线必需资源时，同步加入 `APP_FILES`。
- 安装按钮只有收到 `beforeinstallprompt` 时才显示。
- 不得缓存用户导入的私人文件。只有用户配置并确认使用 AI 时，才可把当前任务所需的最少文本或临时压缩图片直接发送给所选厂商。

## 10. 能力边界

以下能力当前尚未实现，新增前需要明确的数据源、权限和隐私方案：

- 在线饮品卡路里检索。
- 实时股市行情和资讯抓取。
- 云端同步和多设备实时共享。
- 服务端账号、短信验证码或强身份认证。
- 原生 Android APK 打包。

不得用静态占位功能冒充上述真实能力。

## 11. 修改与验收

- 优先沿用现有原生 HTML/CSS/JavaScript 结构，不随意引入框架或外部 CDN。
- 避免无关重构；数据兼容和用户已有记录优先于代码风格调整。
- 每次修改后至少执行：

```bash
node --check app.js
node --check ai.js
node --check service-worker.js
node -e 'JSON.parse(require("fs").readFileSync("manifest.webmanifest", "utf8"))'
```

- 涉及布局时检查 360x800、393x873 和至少一个桌面视口，确认无页面级横向溢出。
- 涉及记录时验证新增、编辑、删除、清空上一条、刷新后留存。
- 涉及数据结构时验证导出后可重新导入且记录数、模块规则一致。
- 涉及 PWA 资源时验证清单、Service Worker、图标均返回成功。
- 发布或交付前重新生成 `neufis-pwa.zip`，并运行 `unzip -t neufis-pwa.zip`。

## 12. 当前访问说明

- 本机测试地址：`http://127.0.0.1:5173/`。
- vivo 临时测试地址取决于电脑当前局域网 IP，README 中的地址可能随网络变化。
- 正式安装应使用 HTTPS 部署地址。
- 浏览器清理站点数据、卸载应用或更换设备前必须先导出备份，否则本地记录可能丢失。
